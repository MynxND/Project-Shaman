# Miko automatic head attachment trial — 2026-10-16

User authorized a single-class tool trial using the existing Miko costume with sword retained. No generators or paid APIs are called. Cancelled pixel-cleanup candidates are not used or published.

Open http://127.0.0.1:8798/docs/design/equipment/miko-auto-head-2026-10-16/index.html after running `node docs/design/equipment/miko-auto-head-2026-10-16/serve.cjs` from the workspace. The main eight-class preview links to this tool. The server binds only to 127.0.0.1 and serves repository files; HTTP is required for browser PNG exports without file-origin canvas restrictions. Closing the server requires restarting it for future use. Standalone file viewing can render, but exporting PNG requires localhost.

`prepare.cjs` extracts all 448 unmodified native 256px body frames from the existing AutoSprite Miko replacement. A constrained skin-component detector finds each exposed neck; data.js retains raw measurements/confidence and source-index provenance. Native original SSR head/hair/face PNGs are copied unchanged. A five-sample weighted tracker follows neck translation and wraps over the selected loop; raw56 uses clamped ends. Fixed first-frame mode permits comparison. Nominal scale is 2.2 native-body pixels per original head pixel; it is an initial calibration, not an inferred artistic fit. Rotation and scale corrections are manual. No new head orientations, relighting or material matching are synthesized.

320px composition adds a 32px horizontal/64px vertical margin around the untouched body. Head pivot comes from existing SSR metadata. A source-body lower overlay puts the collar in front of lower head/hair pixels; this is an approximate horizontal occlusion, not full semantic segmentation. Manual X/Y/scale/angle corrections are keyed by direction or original source frame, with frame values taking precedence. Hair/face selection applies to all directions. Browser storage and JSON import/export are fingerprinted separately from older preview fits; invalid imports are rejected before replacement. Canvas click sets the neck correction in the selected scope.

Export builds either the selected direction or all eight into a ZIP with PNG spritesheets, per-direction atlas (320×320 cells, original source indices, 16FPS durations, neck/angle/scale metadata), and saved fitting JSON. Guide marks never appear in exports. Current trimmed/raw playback selection is respected. UI is disabled during export so controls cannot mutate the export midway. Animations stop on hide/unload.

Validation: check.cjs renders all448 source frames, checks direction/frame fit inheritance, frame55 save/reload, hair/face/rotation, invalid fingerprint rejection, play/pause, eight-direction ZIP and frame clipping, desktop and emulated phone portrait/landscape. See check-report.json and eight-direction-review.png. Visual samples inspected; human artistic approval and physical phone performance remain pending. This is a local review tool, not live-game adoption.

JSZip is bundled from the existing workspace runtime; upstream license is retained in JSZip-LICENSE.markdown. It packages exports locally and sends no data to a generator.
