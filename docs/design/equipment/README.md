## Asset contract

The actual approved source is 128×128, not the brief's assumed 64×64. Keep native density and display at the existing world scale; do not downsample all artwork. Existing main-v1 images are flattened body, hair and clothing. They cannot be losslessly separated into independent hair/top/pants layers. Those independent slots still require reconstructed, reviewed artwork; the current alternate outfit changes the whole clothed body.

`docs/design/rig/skeletons.json` authors four timelines (idle 4, walk 8, attack 8, cast 12 frames) for both bodies and all eight directions. PixelLab `animate_with_skeleton_v3` draws the existing appearance or an outfit variant on each timeline. A generated image can drift from requested joints; skeleton submission alone is not visual proof of alignment. Inspect contact sheets and `/characters` before approval.

`tools/rig/build_rig_v2.py` packages only complete native frame sets. Manifest entries carry actual frame counts, grip/tip, front/back depth, crown and head tilt. Raw frames and job ids stay under `docs/design/rig/raw`. `tools/rig/resume_rig.ps1` resumes missing sets; do not start it for a set already being generated by another worker.

## Rendering and equipment

`CharacterRig.ts` reuses the existing character controller and old rig as a fallback. `ModularRig.ts` adds two persistent images per actor: weapon and headgear. The body/outfit supplies the shared timeline; the main-hand image uses its grip origin and the authored hand-to-tip angle, with depth above/below the body per frame. Headgear follows crown and tilt. Changing equipment preserves the animation phase. World casting uses the same outfit and attachments through `setCastFrame`; old poses are a fallback only for unavailable modular assets.

`EQUIPMENT_VISUALS` is the shared item-to-art model. `PlayerProfile.equipment` is authoritative session data. The `equipment` message accepts `{ slot, itemId }` or `itemId: null` to unequip. The server validates slot, ownership and player state, then broadcasts `PlayerState.look` through schema synchronization. React's bag sends intent and displays the returned profile. Selling or storing a worn item removes it from the synchronized look. Current equipment stat numbers are provisional; this pass does not rewrite combat stat calculation.

The `/characters` inspector uses the exact world renderer without changing any profile. It exposes body, eight facings, four actions, frame scrub, weapons, headgear and outfit. It explicitly reports missing assets rather than drawing a fake clothing overlay. Browser sessions must reload after new manifest entries are packaged.

`/characters/responsive` is a review-only iframe harness for portrait/landscape layout. Browser checks confirmed the same character canvas runtime and selected outfit across orientation changes, and the live world's status window stayed open. See `screens/mobile-*.png`. Physical phone input and performance remain unverified.

## Add an item

1. Add item data with a valid equip slot to shared `catalog.ts` and a matching `EQUIPMENT_VISUALS` entry.
2. For a weapon/headgear, preserve original PixelLab artwork in `docs/design/equipment/raw/<id>/<facing>.png`; package with `tools/equipment/build_items.py`. Weapon south art is the upright local image; grip is a normalized height origin. Do not bake a character into an attachment.
3. For an outfit, create a PixelLab state of the same individual, retain eight rotations and provenance, add the description to `docs/design/rig/outfits.json`, then generate all actions/directions with the shared skeleton. No per-combination body sprites are needed.
4. Build rig assets; inspect frame alignment, occlusion and attachment pivots in `/characters`. Run typecheck/build, equipment unit/network tests and the rig asset verifier. Verify desktop/portrait/landscape before claiming responsive coverage.
